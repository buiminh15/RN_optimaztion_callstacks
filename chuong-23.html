Thử nghiệm Tree Shaking

Tree shaking là kỹ thuật loại bỏ "code chết" của bundler hiện đại — như lắc cái cây để lá khô rụng. Với React Native, nó vẫn còn ở mức thử nghiệm, nhưng đáng biết.

1. Cách hoạt động

Hai bước: ① Tìm code chết (export không được import ở đâu, kiểm tra xóa có an toàn không, lập bản đồ phụ thuộc) → ② Xóa code chết (đánh dấu, xóa khi tối ưu build, chỉ giữ code app thật sự dùng).

ESM vs CommonJS
Thư viện ở dạng ES Module được tree shake hiệu quả hơn. Lịch sử RN luôn dùng CommonJS và mặc định chuyển ESM → CommonJS qua Babel preset; nhiều thư viện trong hệ sinh thái trông chờ phép chuyển đổi này và có thể hỏng nếu không có nó.


Trong production, bundler thực hiện 4 loại tối ưu chính:


Kiểm traViệc làm


Used Exports CheckTìm export nào thật sự được dùng, bỏ phần còn lại


Side Effects CheckNhận diện code thay đổi trạng thái bên ngoài, đảm bảo gỡ an toàn


Export TrackingLập bản đồ liên kết giữa module, theo dõi re-export


Variable UsageTheo dõi cách biến được dùng, tránh xóa nhầm code cần



2. Hỗ trợ trong hệ sinh thái RN



  
Metro
Hiện không hỗ trợ, nhưng có thể "giả" bằng metro-serializer-esbuild (rnx-kit).

  
Expo
Thử nghiệm từ SDK 52.

  
Re.Pack
Hỗ trợ đầy đủ nhờ Webpack/Rspack.




Platform shaking
RN đa nền tảng nên có Platform. Expo và Metro dùng điều này cho kỹ thuật platform-shaking: loại code phụ thuộc nền tảng đích (ios/android/web). Chỉ hoạt động khi import Platform trực tiếp từ react-native.



Bật trong Expo SDK 52


// metro.config.js
const { getDefaultConfig } = require('expo/metro-config');
const config = getDefaultConfig(__dirname);
config.transformer.getTransformOptions = async () => ({
  transform: { experimentalImportSupport: true },
});
module.exports = config;

# .env  (chỉ dùng ở production)
EXPO_UNSTABLE_METRO_OPTIMIZE_GRAPH=1
EXPO_UNSTABLE_TREE_SHAKING=1


experimentalImportSupport dùng phiên bản của Metro cho @babel/plugin-transform-modules-commonjs, giảm mạnh số lần resolve và đơn giản hóa bundle đầu ra; có thể kết hợp inlineRequires (tắt mặc định ở Expo). Có thể gặp lỗi do required cycles hoặc trộn CommonJS/ESM — hãy kiểm tra app build và chạy bình thường.


Re.Pack


Triển khai tree shaking "chiến trận" nhất trong hệ sinh thái RN nhờ Webpack — bật mặc định, Rspack cũng vậy: bạn không cần nghĩ tới.



3. Kỳ vọng cải thiện bao nhiêu?


Benchmark dùng Expensify (app RN mã nguồn mở lớn) so Metro với Re.Pack, nhiều biến thể: Development, Production, Production Minified (Terser), và bản chuyển sang Hermes bytecode (HBC).



  
Biểu đồ · Kích thước bundle (MB)

  

  
 Metro Re.Pack




    
  
  • Production +8% của Re.Pack nghe lạ nhưng đúng kỳ vọng: Rspack chỉ đánh dấu code không dùng, việc xóa thật diễn ra lúc minify.
    • 
  
  • Chuyển sang Hermes bytecode đã bao gồm minify → bản minified cải thiện 11–14% kể cả khi chưa qua Terser.
    • 
  
  • Tổng: kỳ vọng giảm khoảng 10–15% kích thước bundle cuối khi dùng Re.Pack với đủ tối ưu. Chưa đo TTI, nhưng bytecode nhỏ hơn thì nên khởi động nhanh hơn một chút và chiếm ít bộ nhớ hơn.
    • 



Về Expo tree shaking
Nhóm thử trên cùng codebase nhưng kết quả không kết luận được: thấy bundle còn tăng so với Metro, nhiều khả năng do cấu hình sai. Vì tính năng còn thử nghiệm nên không đưa vào benchmark.
