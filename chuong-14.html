Mô hình luồng của TurboModules và Fabric

Muốn viết native module hiệu quả, bạn phải biết code của mình chạy trên luồng nào và vì sao. Chương này đi theo vòng đời một native module — khởi tạo, gọi hàm, hủy — rồi sang Native Views (Fabric).

1. Các luồng có sẵn

Main / UI thread

Xử lý UI, giữ app phản hồi. Giống mọi app native.

JavaScript thread

Chạy JavaScript (không độc quyền).

Native modules thread

Pool dùng chung do React Native cấp riêng cho native module (mqt_v_native).

Ngoài ra bạn, renderer hoặc module bên thứ ba có thể tạo thêm thread nền (xem Chương 17).

2. Vòng đời TurboModule: ai chạy ở luồng nào?

Sách dùng debugger của Xcode và Android Studio để xem từng phương thức được gọi trên luồng nào. Bấm từng sự kiện:

Android

init — khác nhau giữa hai nền tảng

Trên Android, init chạy ở JS thread (mqt_v_js); trên iOS lại chạy ở main thread. Lý do: nếu bạn override init ở iOS, RN giả định bạn có thể đụng tới UIKit (không thread-safe) nên gọi nó trên main queue. Bỏ giả định đó thì module được khởi tạo ở JS thread, giống Android — nhưng đổi nội bộ RN đòi hỏi build từ source; không khuyến khích cho production nhưng là bài học tốt ở môi trường dev.

Eager init (chỉ Android)

Mặc định module khởi tạo lười. Để khởi tạo sớm, đổi tham số thứ tư needsEagerInit sang true trong package:

moduleInfos[AwesomeLibraryModule.NAME] = ReactModuleInfo(
  AwesomeLibraryModule.NAME, AwesomeLibraryModule.NAME,
  false, // canOverrideExistingModule
  true,  // needsEagerInit  ← đổi thành true
  false, // isCxxModule
  true   // isTurboModule
)

Kết quả: init giờ chạy ở mqt_v_native (thread riêng cho TurboModules). Nếu bạn định truy cập instance JavaScript tại đây, phải dùng JavaScript CallInvoker để lên lịch lời gọi lên JS thread.

Gọi hàm đồng bộ (sync)

Hàm sync, ví dụ multiply, được gọi trên JS thread — hợp lý vì ta muốn dừng JS đợi giá trị trả về. Nên cực kỳ cẩn thận:

@objc func multiply(_ a: Double, b: Double) -> NSNumber {
  Thread.sleep(forTimeInterval: 20)   // ❌ chặn JS thread 20 giây
  return a * b as NSNumber
}

Hàm "vô hại" này đóng băng toàn bộ tương tác JS suốt 20 giây — cả app như treo.

Gọi hàm bất đồng bộ (async)

Giống await fetch trên web: lời gọi được giao cho tầng native và xử lý ngoài luồng JS chính — ở đây là native modules thread. Ví dụ multiplyOnBackgroundThread chạy ở Turbo Modules thread, giải phóng JS thread. Nhưng thread này dùng chung cho mọi module nên có thể bận; khi đó hãy tạo thread riêng.

Invalidate (hủy)

Xảy ra khi instance RN bị phá, ví dụ reload Metro. iOS: module phải tuân theo protocol RCTInvalidating và hàm được gọi ở Turbo Modules thread. Android: thread không có tên rõ ràng (sinh tự động) — theo source, đó là thread do ReactHost tạo (pool-2-thread-1).

3. Native Views (Fabric)

Dễ hơn nhiều: hệ điều hành yêu cầu cập nhật view trên main thread; UIKit không thread-safe, nên gần như mọi thứ tạo/chỉnh view xảy ra ở main thread. Cả iOS và Android: view khởi tạo ở main thread; prop updater (updateProps / props setter) cũng ở main thread — dù ở JS bạn thao tác props trên JS thread — vì RN giả định hàm này thao tác trực tiếp view native.

Yoga

Yoga là engine layout đa nền tảng (Flexbox + định vị tuyệt đối) tính layout cho React Shadow Tree — biểu diễn nội bộ bằng C++ của cây component. Không gắn riêng với RN: nhiều app native dùng, và có benchmark còn nhanh hơn auto-layout của iOS. Thao tác trên cây Yoga (ví dụ yoga::Node::measure) chạy ở JS thread.
