Dùng SDK dành riêng cho React Native thay vì web

Điểm hay của React Native là tận dụng hệ sinh thái JavaScript. Nhưng chạy được cùng đoạn JS như trên trình duyệt không có nghĩa nên làm vậy: môi trường mobile có best practice và ràng buộc riêng.

1. Luôn xem lại dependency

Bạn phải cảnh giác: rà soát dependency xem còn dùng được/cần thiết không, hoặc có thể thay bằng giải pháp dành riêng nền tảng tốt hơn. Sách đưa ba ví dụ.

2. Polyfill Intl

Đối tượng Intl cung cấp so sánh chuỗi, định dạng số, ngày giờ theo ngôn ngữ. Có ở mọi trình duyệt hiện đại và một phần trong Hermes:

const number = 123456.789;
const germanFormat = new Intl.NumberFormat('de-DE');
console.log(germanFormat.format(number)); // 123.456,789

Trong dự án RN thường thấy hàng loạt import polyfill từ Format.JS (bản chỉ-JS của API Intl):

import '@formatjs/intl-getcanonicallocales/polyfill';
import '@formatjs/intl-locale/polyfill';
import '@formatjs/intl-numberformat/polyfill';
import '@formatjs/intl-numberformat/locale-data/en';
import '@formatjs/intl-datetimeformat/polyfill';
import '@formatjs/intl-datetimeformat/locale-data/en';
import '@formatjs/intl-pluralrules/polyfill';
import '@formatjs/intl-relativetimeformat/polyfill';
import '@formatjs/intl-displaynames/polyfill';

Hermes từng hỗ trợ hạn chế, nhưng đội Hermes đã cải thiện, nên nhiều polyfill giờ có thể bỏ. Bảng hỗ trợ (theo diff trong sách, tại 1/2025):

Lợi ích

Chỉ riêng việc gỡ vài polyfill đã cắt hơn 430 kB khỏi JS bundle. Code này được nạp sớm ở entry point nên còn có thể cải thiện TTI — chỉ bằng cách bỏ code không cần.

3. Thư viện mật mã

Thay thư viện tính toán nặng bằng bản native. Ví dụ crypto-js (bản JS của crypto Node.js) có thể thay bằng react-native-quick-crypto của Margelo: nhanh hơn tới 58 lần nhờ dùng C++ trực tiếp.

Đặc biệt quan trọng khi cần số ngẫu nhiên an toàn mật mã (CSPRNG), ví dụ sinh seed ví Web3. Không thể dựa vào Math.random() vì không đảm bảo đủ entropy để coi là an toàn.

4. Dùng navigation native

React Navigation cho phép trộn navigator JS và native. Chọn JS Stack (linh hoạt tối đa) hay Native Stack (ít linh hoạt hơn nhưng hiệu năng + giao diện native)? Tab cũng tương tự.

Navigator JSNavigator native
Linh hoạt UIRất caoThấp hơn
Tải cho JS threadCóGiảm → ít bộ nhớ, mượt hơn
Cảm giác nền tảngTự mô phỏngNative feel (header lớn iOS, nút back Android…)

Native Stack

import { createNativeStackNavigator } from '@react-navigation/native-stack';

const MyStack = createNativeStackNavigator({
  screens: { Home: HomeScreen, Profile: ProfileScreen },
});

Dựa trên react-native-screens; API rất giống JS stack nên di chuyển thường không khó.

Native Tabs

import { createNativeBottomTabNavigator } from '@bottom-tabs/react-navigation';

const MyTabs = createNativeBottomTabNavigator({
  screens: { Home: HomeScreen, Profile: ProfileScreen },
});

Từ dự án react-native-bottom-tabs, API gần như tương thích.

5. Ưu tiên thư viện có component native

  • React Native Screens — nền tảng của Native Stack.
  • Zeego — menu native đẹp cho RN + Web, lấy cảm hứng từ Radix UI.
  • React Native Slider — slider dùng primitive native.
  • React Native Date Picker — date picker dùng primitive native.
Bảo vệ người dùng

Không phải lúc nào cũng thay được view JS linh hoạt vô hạn bằng bản native do yêu cầu thiết kế. Nếu có phương án UX tốt hơn, hiệu năng hơn nhưng cần chỉnh nhẹ thiết kế, đừng ngại lên tiếng. UX tốt là cuộc đối thoại giữa sáng tạo của designer và những gì kỹ thuật làm được. Suy cho cùng ta làm tất cả vì người dùng.
