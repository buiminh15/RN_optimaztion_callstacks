Thu nhỏ code bằng R8 (Android)

Kích thước app còn phụ thuộc cả code native. Các công cụ ở chương này có thể cắt thêm vài MB và còn làm app khó bị dịch ngược hơn nhờ obfuscation.

1. Bật R8

ProGuard là công cụ cũ để thu nhỏ, tối ưu và làm rối (obfuscate) code Android. Từ RN ≥ 0.60, Android Gradle Plugin không dùng ProGuard nữa mà dùng R8: nhanh hơn, tương thích tính năng hiện đại như Kotlin (ProGuard không hỗ trợ), và vẫn tương thích file cấu hình ProGuard — nên bạn có thể vẫn thấy chữ "proguard" trong file Android, không sao.

// android/app/build.gradle
def enableProguardInReleaseBuilds = true

Trong template RN mặc định, biến này đặt minifyEnabled = true ở biến thể release, khiến Gradle áp dụng R8 khi đóng gói để phân phối.

Chỉ số có thật trong sách: 9,5 MB (không tối ưu) → 6,3 MB (R8, −33%). Hiệu quả của shrinkResources ở demo chỉ là minh họa, không phải số đo.

Dự án lớn nên kỳ vọng cải thiện nhỏ hơn một chút, nhưng vẫn đáng làm.

2. Quy tắc ProGuard cho R8

R8 cấu hình bằng "ProGuard rules" trong file riêng: điều khiển lớp/phương thức/trường nào giữ lại hay bỏ, và cấu hình mẫu obfuscation (đổi tên class/method) để gây khó dịch ngược. Trong app RN: android/app/proguard-rules.pro (mặc định trống).

Thường không cần tự viết. Nhưng nếu sau khi loại bỏ code chết app chạy sai (một số dependency giả định tên class), bạn phải thêm class cần giữ — ví dụ Firebase:

# proguard-rules.pro
-keep class io.invertase.firebase.** { *; }
-dontwarn io.invertase.firebase.**

# Obfuscation bật mặc định khi minifyEnabled. Muốn tắt:
-dontobfuscate

3. Thu nhỏ tài nguyên

Khi R8 đã bật ở biến thể release, bật thêm nén tài nguyên (resource minification) để giảm tiếp:

  1. Gộp tài nguyên trùng lặp.
  2. Tối ưu PNG: giảm độ sâu màu, nén không mất dữ liệu.
  3. Xử lý vector drawable.
android {
  buildTypes {
    release {
      // Code shrinking, obfuscation, optimization — chỉ cho release; cần debuggable false
      minifyEnabled true
      // Resource shrinking; cần minifyEnabled = true
      shrinkResources true
    }
  }
}
Kiểm thử kỹ trước khi phát hành

Loại code chết có thể làm hỏng những chỗ dùng reflection. Hãy test app (nhất là các thư viện dùng tên class) rồi mới đẩy lên store. Dùng Ruler (Chương 20) để kiểm tra chênh lệch download/install size.
