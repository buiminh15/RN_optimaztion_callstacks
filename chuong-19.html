Phân tích kích thước JS bundle

Phần 1–2 chủ yếu cải thiện FPS ở runtime. Phần 3 xử lý thời điểm build để app khởi động nhanh hơn — tức cải thiện TTI. Mở đầu là hiểu: ta đang đóng gói gì và gửi gì cho người dùng.

1. Bundler và JS bundle

Giống web, dev RN dùng bundler để biến nhiều file nguồn (TypeScript, HTML, CSS, JPG, MP4…) được import qua một entry file thành định dạng mà JS engine đích hiểu — thường là một file .js cùng tài nguyên khác.

  • Metro: bundler mặc định của RN. Hỗ trợ mọi nền tảng, kể cả web nhưng thiếu code splitting và tree-shaking.
  • Webpack/Rspack (qua Re.Pack): thay thế Metro, phổ biến ở web.
  • Dev: bundle không chứa JS mà lấy từ dev server → Hot Module Replacement / Fast Refresh (cập nhật dưới 1 giây).
  • Release: bundle chứa file .jsbundle là Hermes Bytecode, không kết nối dev server. Do script native (Xcode/Gradle) chạy npx react-native bundle rồi đưa qua compiler Hermes.

2. Vì sao vẫn phải quan tâm kích thước JS?

Bundle gồm code của bạn, code thư viện bên thứ ba và các transitive dependency. Kích thước ít nhiều ảnh hưởng đường khởi tạo của app. Mọi cách làm nhỏ đi đều xoay quanh một ý: bỏ code không cần ở thời điểm đó. Và thời điểm là tất cả:

if (__DEV__) {            // có thể loại bỏ khỏi bản production
  // ...
}
if (Platform.OS === 'ios') {   // có thể loại bỏ khỏi bundle Android
  // ...
}

3. Hermes bytecode thay đổi cuộc chơi

Nếu app cập nhật từ 2022 và dùng RN ≥ 0.70, bundle cuối thường không chứa JS thô mà là bytecode do Hermes sinh. (Hermes là engine duy nhất tạo bytecode dùng được trong RN; V8 về mặt kỹ thuật làm được tối ưu ahead-of-time tương tự bằng heap snapshot.)

So sánh · Từ file JS đến khi chạy

Vì thế các thủ thuật web — nhất là code splitting hay tối ưu mạnh kích thước bundle ban đầu — không áp dụng trực tiếp: RN không cần tải về (JS đã nằm trong app), và nhờ Hermes còn bỏ qua cả bước nạp vào bộ nhớ và parse.

Nhưng vẫn quan trọng

Chọn thư viện nhỏ hơn, bỏ code cũ, chỉ nạp thư viện cần thiết trên đường khởi tạo. Kích thước bytecode ảnh hưởng kích thước app (tải về/khởi tạo chậm hơn); JS chạy nhiều trên đường khởi tạo ảnh hưởng TTI. Tệ hơn, khi JS này nạp native module sẽ tạo thêm việc cho phía native, làm mất lợi ích lazy loading của TurboModule.

TurboModule là lazy

Native Module kiến trúc cũ khởi tạo eager lúc mở app; TurboModule chỉ chạy khi JS gọi tới — cải thiện TTI rõ rệt khi lên New Architecture.

Ví dụ: import thư viện component có hàng trăm component nhưng chỉ dùng chục cái, qua barrel file, không tree shaking/Babel plugin tối ưu → mọi component được nạp ngay trên đường khởi tạo; vài cái gọi TurboModule riêng nên các module này cũng khởi tạo sớm thay vì không bao giờ hoặc muộn hơn. 4. Công cụ xem bên trong bundle

source-map-explorer

Phân tích bất kỳ JS bundle nào có source map qua giao diện web — cho cái nhìn tổng quan những gì tới tay người dùng, dễ thấy "ngoại lai" vô tình lọt vào hay tàn dư tính năng cũ, kể cả kích thước code của chính bạn.

> npx react-native bundle \
    --entry-file index.js \
    --bundle-output output.js \
    --platform ios \
    --sourcemap-output output.js.map \
    --dev false \
    --minify true

> npx source-map-explorer output.js --no-border-checks

Metro sinh mapping cột/dòng không hợp lệ nên cần cờ --no-border-checks. Tool vẫn dựng được UI nhưng bạn có thể mất tới 30% thông tin → che bớt cơ hội tối ưu. Muốn thêm thông tin, dùng Expo Atlas.

Expo Atlas

> EXPO_UNSTABLE_ATLAS=true npx expo start --no-dev
# hoặc
EXPO_UNSTABLE_ATLAS=true npx expo export
> npx expo-atlas

Dành cho dự án Expo, tích hợp sâu vào pipeline Metro. Có thể chạy không cần Expo CLI qua dự án expo-atlas-without-expo.

Nếu dùng Re.Pack với Rspack/Webpack

Hệ công cụ phong phú hơn (Rspack gần ngang hệ Webpack, hiệu năng tốt hơn).

CLI Rspack hỗ trợ sẵn qua --analyze (dùng webpack-bundle-analyzer bên dưới):

> rspack build --analyze

Sinh stats.json bằng lệnh bundle của Re.Pack, rồi đưa vào công cụ phân tích. Có thể so sánh hai file stats để thấy bundle tăng/giảm theo thời gian.

> npx react-native bundle --platform android --entry-file index.js \
    --dev false --minify true --json stats.json
> npx bundle-stats --html --json stats.json

Module bundle size của Rsdoctor phân tích đầu ra Rspack: kích thước tài nguyên, package trùng lặp, quan hệ tham chiếu module.

const { RsdoctorRspackPlugin } = require('@rsdoctor/rspack-plugin');
module.exports = {
  plugins: [
    process.env.RSDOCTOR && new RsdoctorRspackPlugin({ /* options */ }),
  ].filter(Boolean),
};

Chạy với biến môi trường RSDOCTOR=true để mở UI.
