Làm native module nhanh hơn

Khi JavaScript chưa đủ, bạn có thể xuống Swift/Kotlin, hoặc thậm chí C++ để lấy hiệu năng và tái sử dụng code. Chương này tổng hợp các thực hành tốt khi viết native module.

1. Dựng khung nhanh với Builder Bob

Tạo một thư viện RN mới cần rất nhiều boilerplate: hỗ trợ kiến trúc cũ lẫn mới, codegen từ typing TypeScript/Flow, hạ tầng chạy/test/publish lên npm. React Native Builder Bob làm hộ bạn:

> npx create-react-native-library@latest library-name

Nó hỏi tên package, bạn muốn Turbo module, Fabric view hay thư viện thuần JS, và ngôn ngữ ưa thích. Không phải lúc nào cũng muốn publish — với module riêng cho dự án, dùng cờ --local (local modules).

2. Dùng ngôn ngữ hiện đại: Kotlin và Swift

Android

Kotlin (JetBrains) kế thừa Java, được Google công bố là ngôn ngữ ưu tiên năm 2019, tương thích hoàn toàn với Java. Một phần RN đã được viết lại bằng Kotlin; thư viện do Builder Bob sinh ra đã dùng Kotlin.

iOS

Swift (2014) thay Objective-C dài hạn; dùng song song được với Obj-C để di chuyển dần. Thách thức: tương tác C++. RN New Architecture dùng C++ cho lõi, nên iOS nội bộ vẫn dựa vào Objective-C và Objective-C++, còn Swift–C++ interop còn rất mới và thử nghiệm.

Cách làm: tạo một "wrapper" nhỏ nối Objective-C sang Swift. Hơi rườm rà nhưng chạy được:

  1. Bật Swift trong Podspec: 
    - s.source_files = "ios/**/*.{h,m,mm,cpp}"
+ s.source_files = "ios/**/*.{h,m,mm,cpp,swift}"
  2. Tạo file Swift trong Xcode, đặt trong thư mục iOS của module, chọn "Yes" để tạo Bridging Header.
  3. Sửa header thư viện để Swift không lỗi vì kiểu C++ (Swift không hiểu C++): 
    #import <Foundation/Foundation.h>
#if __cplusplus
#import "ReactCodegen/RNAwesomeLibrarySpec/RNAwesomeLibrarySpec.h"
#endif
@interface AwesomeLibrary : NSObject
#if __cplusplus <NativeAwesomeLibrarySpec> #endif
@end
  4. Import header chính trong Bridging Header: #import "AwesomeLibrary.h"
  5. Viết extension Swift và lộ ra Obj-C bằng @objc: 
    extension AwesomeLibrary {
  @objc func multiply(_ a: Double, b: Double) -> NSNumber { a * b as NSNumber }
}
  6. Trong file .mm, dùng RCT_EXTERN_METHOD: 
    #import "AwesomeLibrary.h"
#if __has_include("awesome_library/awesome_library-Swift.h")
#import "awesome_library/awesome_library-Swift.h"   // khi dùng framework tĩnh/động
#else
#import "awesome_library-Swift.h"
#endif

@implementation AwesomeLibrary
RCT_EXPORT_MODULE()
RCT_EXTERN_METHOD(multiply:(double)a b:(double)b);
@end

    Xcode sinh header <library-name>-Swift.h (có tiền tố tên thư viện ở chế độ framework), nên cần kiểm tra bằng __has_include. RCT_EXTERN_METHOD ánh xạ hàm Obj-C sang lời gọi Swift. Cộng đồng đang làm hỗ trợ Swift mặc định nên boilerplate này hy vọng sẽ biến mất.

3. Tận dụng luồng nền

Trên web chủ yếu một luồng (web worker khác hơn một chút). Trong RN bạn khai thác được sức mạnh của thiết bị. Mặc định hàm đồng bộ của Turbo Module chạy trên JS thread (cả iOS lẫn Android). Muốn đẩy việc sang nền, viết hàm async:

Demo · Hàm sync chặn JS thread, hàm async thì không

Bộ đếm "JS tick" tăng mỗi 100 ms khi JS thread rảnh. Gọi native function mất 2 giây theo hai cách.

Native (background) thread

iOS: DispatchQueue

@objc func multiplyOnBackgroundThread(
  _ a: Double, b: Double,
  resolve: @escaping RCTPromiseResolveBlock,
  reject: RCTPromiseRejectBlock
) {
  DispatchQueue.global().async {
    resolve(a * b)        // báo kết quả về JS
  }
}

Khối trong DispatchQueue.global() chạy khi hàng đợi nền toàn cục sẵn sàng; bên trong gọi resolve() để thông báo cho hàm JS.

Android: Kotlin coroutines

Không truy cập thread trực tiếp mà dùng coroutine — một phần của framework đồng thời Kotlin, dễ đọc, dễ bảo trì. Coroutine không gắn với thread vật lý: hàng nghìn coroutine có thể chạy trên vài thread.

@ReactModule(name = AwesomeLibraryModule.NAME)
class AwesomeLibraryModule(reactContext: ReactApplicationContext) : NativeAwesomeLibrarySpec(reactContext) {
  private val moduleScope = CoroutineScope(Dispatchers.Default + SupervisorJob())

  override fun invalidate() {
    super.invalidate()
    moduleScope.cancel()          // ✅ tránh memory leak
  }

  override fun multiplyOnBackgroundThread(a: Double, b: Double, promise: Promise?) {
    moduleScope.launch { promise?.resolve(a * b) }
  }
}

Đặt breakpoint, bạn sẽ thấy hàm chạy trên worker thread thay vì main thread (cả hai nền tảng). Xem thêm các lưu ý ở Chương 14.

4. Thay code độc lập nền tảng bằng C++

Logic không phụ thuộc nền tảng có thể viết lại bằng C++ để tăng tốc rõ rệt; C++ chạy trên iOS, Android, Windows… Đổi lại: phải rất cẩn thận với luồng và memory leak (xem Chương 13). RN website có hướng dẫn C++ Turbo Modules.

Tại 1/2025, C++ Turbo Module không hỗ trợ autolinking trên iOS. Để khỏi sửa AppDelegate, dùng registerCxxModuleToGlobalModuleMap trong một class Obj-C nhỏ, tận dụng + load (gọi một lần khi class được nạp vào runtime lúc khởi động):

#include <ReactCommon/CxxTurboModuleUtils.h>
@implementation YourModule
+ (void)load {
  facebook::react::registerCxxModuleToGlobalModuleMap(
    std::string(facebook::react::YourModule::kModuleName),
    [&](std::shared_ptr<facebook::react::CallInvoker> jsInvoker) {
      return std::make_shared<facebook::react::YourModule>(jsInvoker);
    });
}
@end

5. Chi phí ẩn khi bắc cầu giữa các ngôn ngữ

Cầu nốiChi phíGhi chú
Objective-C++Trộn Obj-C với C++ gần như 0 (compile-time) — nhưng gọi method Obj-C phải tra bảng method (dynamic)Turbo Module viết bằng Obj-C vẫn bị tra bảng.
Swift ↔ C++Swift dùng vtable theo class (như C++); interop với C++ gần như 0Lý do Nitro Modules (bỏ qua Obj-C, dùng C++ interop) có thể nhanh hơn đáng kể.
JNI (Android)Mỗi lần gọi tra bảng hàm → overheadGọi Kotlin→C++ trực tiếp qua JNI chậm hơn nhưng đáng với tác vụ dài. Với C++ Turbo Module, JNI chủ yếu dùng lúc khởi tạo; runtime JS giữ tham chiếu C++ qua JSI nên gọi trực tiếp, không overhead.
