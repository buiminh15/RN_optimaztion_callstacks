Đo TTI (Time to Interactive)

TTI là thời gian từ lúc chạm icon đến lúc người dùng thấy nội dung có ý nghĩa và tương tác được. Đây là một trong hai chỉ số mọi app phải theo dõi. Chương này chỉ cách đo nó đáng tin cậy.

1. Vì sao TTI quan trọng và "bao nhiêu là đủ"?

TTI ảnh hưởng tới trải nghiệm, sự hài lòng, giữ chân người dùng và doanh thu. iOS thậm chí dùng machine learning để prewarm các app bạn hay mở, khiến app mở nhanh hơn tới ~40% — tạo ấn tượng cả hệ sinh thái nhanh dù một số app thật ra rất chậm.

Nhiều báo cáo (chất lượng lẫn lộn) nói người dùng mong app mở trong 2–4 giây. Sách khuyên: tin dữ liệu của bạn, hoài nghi báo cáo bên ngoài. TTI nên càng thấp càng tốt, nhưng có giới hạn hợp lý: có đáng tốn nhiều tháng công sức để từ 2,9 s xuống 2,3 s trên máy Android tham chiếu không? Chỉ có hành vi người dùng của bạn trả lời được.

2. Đo cho đáng tin: chỉ đo cold start

App có thể khởi động cold, warm/hot hoặc được prewarm. Ví dụ app tin tức bạn mở lúc 8 giờ sáng mỗi ngày: lần "cold" mất ~10 s, vài ngày sau chỉ còn ~6 s. Còn nếu mở buổi sáng rồi quay lại buổi tối khi app còn ở background, chỉ cần render phần React — nhanh hơn rất nhiều.

Sai lầm

Đo mọi lần khởi động rồi lấy trung bình → số liệu vênh vô nghĩa, không biết đã cải thiện hay thụt lùi. Chỉ đo cold boot, loại bỏ prewarm/warm/hot.

Công cụ ghi marker

Cần native module hoặc thư viện: sách dùng react-native-performance, nó mở class RNPerformance cho iOS/Android để tạo marker tùy chỉnh, rồi truy cập ở React bằng API performance như web:

// iOS
RNPerformance.sharedInstance().mark("myCustomMark")
// Android
RNPerformance.getInstance().mark("myCustomMark");

// React / JS
import performance from 'react-native-performance';
performance.measure('myCustomMark');
performance.getEntriesByName('myCustomMark');
// [{ name: "myCustomMark", entryType: "myCustomMark", startTime: 98, duration: 2137 }]
Lưu ý

Thư viện có sẵn marker như nativeLaunchStart, runJsBundleEnd. Nhưng nativeLaunchStart đo ở pre-main (trong lúc prewarm), phần còn lại đo sau prewarm — có thể cần lọc bỏ hoặc tạo marker riêng trong main().

4. Triển khai từng giai đoạn

① Native Process Init — xác định cold start & foreground

// cold start?
let isColdStart = ProcessInfo.processInfo.environment["ActivePrewarm"] == "1"

// chỉ đo khi ở foreground — AppDelegate.swift
override func application(_ application: UIApplication,
  didFinishLaunchingWithOptions launchOptions: ...) -> Bool {
  if application.applicationState == .active { isForegroundProcess = true }
  return true
}

// nativeLaunchStart
var tp = timespec(); clock_gettime(CLOCK_THREAD_CPUTIME_ID, &tp)
// nativeLaunchEnd ~ khi một native module được khởi tạo
+ (void) initialize
// cold start? — cần onActivityCreated nên dài dòng hơn
class MainApplication : Application(), ReactApplication {
  var isColdStart = false
  override fun onCreate() {
    super.onCreate()
    var firstPostEnqueued = true
    Handler().post { firstPostEnqueued = false }
    registerActivityLifecycleCallbacks(object : ActivityLifecycleCallbacks {
      override fun onActivityCreated(activity: Activity, savedInstanceState: Bundle?) {
        unregisterActivityLifecycleCallbacks(this)
        if (firstPostEnqueued && savedInstanceState == null) isColdStart = true
      }
    })
  }
  // foreground?
  private fun isForegroundProcess(): Boolean {
    val info = ActivityManager.RunningAppProcessInfo()
    ActivityManager.getMyMemoryState(info)
    return info.importance == IMPORTANCE_FOREGROUND
  }
}
// nativeLaunchStart
Process.getElapsedCpuTime()
// nativeLaunchEnd ~ khi ContentProvider được tạo
class StartTimeProvider : ContentProvider() { override fun onCreate(): Boolean {} }
Cẩn thận pre-main

Các initializer pre-main chạy sớm — có thể hàng giờ trước khi app iOS thật sự được mở và main() chạy. Phải tính chênh lệch với thời điểm process start.

⑤ React App Render — screenInteractive

Marker này quyết định TTI tổng và không có chỗ đặt chung: tùy app, bạn quyết định khi nào người dùng tương tác an toàn. Cơ bản: đặt trong mount ban đầu của useEffect ở màn hình chính; sau đó tìm điểm tốt hơn, ví dụ khi nội dung cấp cao nhất mà người dùng thường bắt đầu đã hiển thị.

export default function HomeScreen() {
  useEffect(() => { /* performance.mark('screenInteractive') */ }, []);
  return <TabNavigator />;
}

5. Dùng dữ liệu

Ghép tất cả bạn có "bản đồ" toàn bộ pipeline khởi động, từ native init đến một hoặc nhiều màn hình tương tác được. Gửi dữ liệu lên database hoặc nền tảng đo real-user: quan sát trên nhiều thiết bị và thay đổi theo thời gian; tương quan TTI với chỉ số thành công của khách hàng. Dữ liệu này nên ảnh hưởng ưu tiên của team: lúc nào cần tối ưu, lúc nào dừng các tối ưu không còn hiệu quả.
