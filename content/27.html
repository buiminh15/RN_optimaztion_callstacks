Tắt nén JS bundle (Android)

Nén file thường là điều tốt — nhưng với JS bundle của Hermes, nén lại làm mất một tối ưu quan trọng và kéo TTI chậm đi. Đổi một chút dung lượng cài đặt để lấy tốc độ khởi động.

1. Vấn đề

APK và AAB là archive nén. Khi đóng gói, hệ thống build Android nén các file nhằm giảm kích thước tải và lưu trữ — nó không phân biệt định dạng, chỉ thường bỏ qua file vốn đã nén tốt (.png, .jpg).

Với app RN dùng Hermes, JS bundle cuối nằm trong index.android.bundle. Dù là binary, nó vẫn bị coi như tài nguyên khác nên bị nén theo mặc định.

Hệ quả

File đã nén sẽ bị bỏ qua khi memory mapping (mmap) (xem Pull Request vào core RN). Điều này vô hiệu hóa một trong những tối ưu quan trọng nhất của Hermes → TTI tệ hơn.

2. Cách tắt nén

Cập nhật từ chính sách của RN

Tính đến 17/02/2025, React Native Core Team đang đưa hành vi này vào mặc định — nhiều khả năng có trong RN 0.79. Dù dùng phiên bản nào, bạn có thể tự làm ngay:

// android/app/build.gradle
android {
  + androidResources {
+   noCompress += ["bundle"]
+ }
}

Kết quả: index.android.bundle không còn bị nén → kích thước app tăng, nhưng Hermes tận dụng được memory mapping và nạp bundle nhanh hơn.

3. Đánh đổi

Chỉ sốThay đổi
Install sizeTăng (APK thử nghiệm 75,9 MB: +6,1 MB, +8%)

TTIGiảm 450 ms (−16%) trong thử nghiệm đầu
Vẫn phải đo

Hiếm khi, nhưng có thể app của bạn không to lên vì nhiều lý do. Hãy đo kết quả và quan sát hành vi người dùng để chắc đây là lợi ròng. Rất có thể lợi ích sẽ lớn hơn chi phí.

Bổ sung: PR về memory mapping JS bundle được sách dẫn trong repo facebook/react-native (tìm "mmap bundle uncompressed") · Hermes trong RN.

Kiểm tra nhanh

1. Vì sao bundle nén làm TTI tệ hơn?
Memory mapping cần file không nén.
2. Tắt nén ảnh hưởng thế nào đến download size?
Tải qua mạng vẫn nén; chỉ chiếm nhiều chỗ hơn khi đã cài.
3. Cấu hình nào tắt nén cho file .bundle?
Đặt trong app/build.gradle.
