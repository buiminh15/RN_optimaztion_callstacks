Profile phần native của React Native

Khi React Native DevTools không đủ, ta chuyển sang công cụ của nền tảng: Xcode Instruments (iOS) và Android Studio Profiler (Android). Bạn sẽ học cách đọc đúng thông tin từ chúng.

1. Vì sao cần profiler native?

Nút thắt xảy ra ở cả hai phía. Ngoài CPU, bộ nhớ, mạng, pin cũng quan trọng với người dùng mobile — nếu bỏ độ sáng màn hình ra thì pin gần như phản ánh mức tải CPU.

Kịch bản mẫu của sách dùng cho cả hai nền tảng: một app render 5.000 view trong ScrollView, re-render mỗi lần bấm nút (đổi state), thêm một ảnh bật/tắt để đẩy danh sách xuống và buộc layout lại.

Hai nền tảng · Hai công cụ

Debug Navigator

Khi app đang chạy và gắn với debugger của Xcode, panel bên hiển thị nhanh: CPU (% theo một core nên có thể > 100%, hay gặp ở app RN), Memory, Disk (SSD chậm hơn RAM), Network (TCP/IP, UDP/IP). Còn có View Hierarchy — xem Chương 15.

Instruments → Time Profiler

  1. Xcode → Open Developer Tool → Instruments.
  2. Chọn template Time Profiler (có CPU Profiler).
  3. Chọn thiết bị và app ở dropdown cạnh nút đích, nhấn nút ghi đỏ. Profiler khởi động lại app và lấy mẫu CPU từ đầu.
  4. Tái hiện lỗi (bấm nút, bật/tắt ảnh), rồi dừng ghi.
  5. Phóng to khoảng quan tâm (Cmd +) — ví dụ ~1,3 s trong 27 s dữ liệu.

Cách đọc: một spike ngắn trên UI thread (tên app), tiếp theo là CPU nặng trên JS thread và rất nhiều việc trên UI thread. Trong lúc UI thread tải cao xuất hiện Microhang; JS thread tải cao thì không. Nghĩa là UI thread bận nên không phản hồi tương tác ngay. Nếu thread bị chặn hoàn toàn sẽ hiện Hang — ưu tiên điều tra cao. Công cụ Hangs đi kèm Time Profiler giúp phát hiện nhanh.

Thiết kế đáng trân trọng

Bạn có thể chặn hẳn JS thread mà người dùng vẫn bấm được các phần tử native; chỉ là sự kiện chưa truyền về JS ngay. Đây là hệ quả tốt của mô hình luồng RN.

Mẹo: lọc Call Tree để ẩn thư viện hệ thống; invert call tree để có bottom-up sắp theo "weight" (đơn vị counts, Mc = mega counts = hàng triệu mẫu); chuyển giữa Call Tree và Flame Graph; ghim (pin) JS thread bằng dấu + để so với UI thread và hang trên cùng timeline. Kết luận của sách: lưu 5k phần tử trong ScrollView không tối ưu.

Android Profiler

Mở bằng View → Tool Windows → Profiler hoặc nút "Profiler: Run 'app' as profileable". Nếu không được, cần debuggable build hoặc tự tạo bản profileable theo hướng dẫn chính thức.

  1. Kết nối app đang chạy (profileable) trên thiết bị.
  2. Chọn task Find CPU Hotspots → Start profiler task.
  3. Thực hiện cùng kịch bản (bấm nút vài lần) rồi dừng → hiện flame graph theo luồng.
Chọn thiết bị yếu nhất

Hệ sinh thái Android phân mảnh hơn iOS nhiều (điện thoại, tablet, TV; thấp → cao cấp). Hãy profile trên thiết bị/emulator thấp cấp nhất, và dùng dữ liệu real-user monitoring nếu có.

Cách đọc: phóng vào JS thread ngay sau khi bấm: nhiều spike ~1 ms từ Hermes duyệt qua 5k view; tổng cộng > 240 ms — vượt xa ngân sách 16,6 ms. Khoảng 1/3 thời gian nằm ở pha commit của reconciliation (layout bằng Yoga rồi mới mount và vẽ).

Cuộn lên main thread: có event handler lúc nhấn xuống và lúc nhả tay; thời điểm nhả khớp gần như hoàn hảo với lúc JS bắt đầu tăng việc, nhờ lời gọi JSI đồng bộ. Ở kiến trúc cũ, thông tin phải được serialize và phát qua bridge → thêm overhead.

Như mọi profiler: xem top-down hoặc bottom-up, lọc theo thư viện (ví dụ "hermes"). Có thể xuất trace và mở bằng công cụ khác.

Perfetto

Công cụ system profiling/trace analysis, bổ sung cho Trace Viewer của Android Studio. Tải trace lên ui.perfetto.dev để phân tích từ góc nhìn khác (ví dụ memory trace do Android Studio tạo).

Tính nhanh · 240 ms là bao nhiêu khung hình?

Công việc JS:
≈ khung hình bị bỏ ở 60 Hz
≈ khung hình bị bỏ ở 120 Hz
Kỹ năng đáng đầu tư nhất

Biết dùng profiler giúp bạn sửa mọi loại vấn đề hiệu năng ở bất kỳ codebase nào, kể cả code bạn không viết.

Kiểm tra nhanh

1. Trong Instruments, "Microhang" trên UI thread cho thấy gì?
Hang hoàn toàn chặn thread; microhang là bản nhẹ hơn.
2. Nên profile Android trên thiết bị nào?
Hệ sinh thái phân mảnh; máy yếu lộ vấn đề rõ nhất.
3. Perfetto dùng để làm gì?
Tải trace lên ui.perfetto.dev.
