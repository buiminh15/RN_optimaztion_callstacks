Tải code từ xa khi cần

Trên web, tải code từ server là chuyện thường. Trên mobile thì JS đã nằm sẵn trong app (chạy offline), nên đây là mô hình tư duy khác — và chỉ đáng dùng trong một số trường hợp.

1. Khi nào nên cân nhắc?

Hiệu quả của code splitting / tải code động phụ thuộc engine JS:

Hermes (mặc định)

Lợi ích rất nhỏ: Hermes dùng memory mapping nên đã chỉ đọc đúng phần bytecode cần.

JavaScriptCore / V8

Code splitting vẫn cải thiện đáng kể thời gian tải ban đầu nhờ nạp chunk theo yêu cầu.

Vì vậy hiếm app RN hiện đại hưởng lợi, nhưng vẫn có các trường hợp nên thử:

  • Bạn không dùng Hermes.
  • Có nhu cầu cụ thể về tải code từ xa.
  • Kích thước app ảnh hưởng đáng kể tới trải nghiệm.
  • App quá lớn cho Google Play (giới hạn 200 MB).
  • Xây kiến trúc microfrontend bằng Module Federation.
  • Bạn đã dùng hết các kỹ thuật tối ưu khác.

2. Chuyển sang Re.Pack

Metro mặc định không hỗ trợ code splitting cho production. Cần Re.Pack — công cụ xây trên Webpack (nay có cả Rspack, build nhanh hơn Metro trong hầu hết trường hợp) để bundling RN. Cần thêm công di chuyển cấu hình, nhưng đáng khi đã hết cách khác.

> npx @callstack/repack-init

Lệnh này áp dụng thay đổi cần thiết và hướng dẫn bạn. Sau đó npm start sẽ phục vụ JS bằng dev server của Re.Pack (Webpack/Rspack) thay vì Metro. Có thể gặp vài điểm không tương thích — theo dõi hướng dẫn migration chính thức.

3. Tách bundle

Cách phổ biến: dynamic import + React.lazy + Suspense.

// Trước — import thường
import FeatureComponent from './FeatureComponent';

// Sau — tạo điểm tách
const FeatureComponent = React.lazy(() =>
  import(/* webpackChunkName: "feature" */ './FeatureComponent')
);

Khi bundle, FeatureComponent thành file riêng feature.chunk.bundle. Ví dụ cho một màn hình:

-import SettingsScreen from './screens/SettingsScreen';
+const SettingsScreen = React.lazy(() =>
+  import(/* webpackChunkName: "settings" */ './screens/SettingsScreen')
+);

const App = () => (
  + <Suspense fallback={<LoadingSpinner />}>
      <SettingsScreen />
  + </Suspense>
);

Demo · Main bundle và chunk tải theo yêu cầu

Bấm "Mở Settings" để mô phỏng việc Re.Pack tải chunk settings từ CDN lần đầu.

Tải chunk từ xa: ScriptManager

Comment webpackChunkName đặt tên chunk, giúp bước cuối: chỉ cho Re.Pack cách lấy chunk không còn nằm trong main bundle:

// index.js
import { ScriptManager, Script } from '@callstack/repack/client';

ScriptManager.shared.addResolver((scriptId) => ({
  url: __DEV__
    ? Script.getDevServerURL(scriptId)                // dev: từ dev server
    : `https://my-cdn.com/assets/${scriptId}`,        // production: từ CDN
}));

AppRegistry.registerComponent(appName, () => App);

ScriptManager là client runtime của Re.Pack, cấu hình cách tìm và nạp các chunk ngoài main bundle. Còn nhiều yếu tố khác (caching, triển khai CDN production…) — xem tài liệu Re.Pack.

4. Module Federation

Một use case hấp dẫn: chỉ tải tính năng mà người dùng cụ thể cần. Ví dụ app doanh nghiệp lớn có nhiều vai trò, mỗi vai trò dùng bộ chức năng khác nhau → tải theo quyền/tuỳ chọn thay vì gộp hết.

Với tình huống phức tạp hơn — nhiều team độc lập, muốn tự chủ phát triển và triển khai — có thể xét microfrontend bằng Module Federation: giải pháp đã được kiểm chứng trên web và mobile nhờ Re.Pack.

Đừng chọn microfrontend chỉ để giảm bundle

Kiến trúc này có độ phức tạp riêng; chỉ nên chọn khi lợi ích về tổ chức/quy trình phát triển vượt chi phí. Một khó khăn lớn là quản lý phiên bản — tự làm khá nặng nề. Nếu chấp nhận dịch vụ bên thứ ba, sách gợi ý Zephyr Cloud: đơn giản hóa vấn đề này, deploy dưới 1 giây, tích hợp chính thức với Re.Pack.
