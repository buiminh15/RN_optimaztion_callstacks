Animation mượt, không rớt khung hình

Animation ≥ 60 FPS là yếu tố quyết định cảm giác "chau chuốt". Bí quyết trong React Native: chạy animation trên UI thread, đừng để nó phụ thuộc vào JS thread đang bận.

1. Main thread (UI thread) là gì?

Main thread — còn gọi là UI thread (hai tên là một) — chịu trách nhiệm vẽ giao diện và xử lý thao tác chạm. Mọi cập nhật hình ảnh xảy ra ở đây. Nó khác với JS thread, nơi phần lớn code React Native của bạn chạy.

Demo · Animation trên UI thread vs trên JS thread

Trong trình duyệt: hình tròn trên chạy bằng CSS transform (giống animation ở UI thread, trình duyệt tự vẽ), hình dưới được cập nhật bằng JavaScript mỗi khung (như animation ở JS thread). Bấm nút để chặn luồng JS 1,5 giây.

🧵 UI thread — CSS animation
🧵 JS thread — cập nhật bằng JavaScript
 → bóng JS đứng yên, bóng CSS vẫn chạy.
Lưu ý

Đây chỉ là phép ẩn dụ trong trình duyệt. Trong RN, animation viết bằng Animated API thuần JS (không native driver) sẽ giật như bóng dưới khi JS thread bận.

2. React Native Reanimated và worklet

Muốn thêm animation, hãy dùng React Native Reanimated — tiêu chuẩn của ngành (tính đến 1/2025 có gần 1 triệu lượt tải mỗi tuần). Nó chạy animation thẳng trên UI thread nhờ worklet: những hàm JavaScript ngắn có thể chạy trên UI thread (và cả trên JS thread như hàm thường).

Ý tưởng lan rộng

Worklet do Reanimated tiên phong và đã xuất hiện ở thư viện khác như VisionCamera, LiveMarkdown. Các thư viện này dùng createWorkletRuntime để tạo JS runtime riêng, chạy worklet trên luồng khác.

Phần lớn code trong Reanimated mặc định chạy trên UI thread, ví dụ useAnimatedStyle:

const style = useAnimatedStyle(() => {
  console.log('Running on the UI thread');
  return { opacity: 0.2 };
});

runOnUI và runOnJS

runOnUI chạy một đoạn code thủ công trên UI thread — dùng với useEffect để bắt đầu animation khi mount/unmount, hoặc với measure, scrollTo (chỉ có trên UI thread).

runOnUI(() => { console.log('Running on the UI thread'); });

runOnJS làm ngược lại: gọi hàm không phải worklet (ví dụ từ thư viện ngoài, analytics, cập nhật state) từ UI thread về JS thread:

const notifyCompletion = () => {            // chạy ở JS thread
  console.log('Animation completed!');       // analytics, setState…
};

const animatedStyle = useAnimatedStyle(() => {
  if (progress.value >= 1) {
    runOnJS(notifyCompletion)();           // UI thread → JS thread
  }
  return {
    opacity: progress.value,
    transform: [{ scale: withSpring(progress.value) }],
  };
});

Chọn luồng nào?

UI thread
  • Animation, transform, thay đổi layout
  • Thao tác trực tiếp lên phần tử UI
JS thread
  • Tính toán phức tạp, xử lý dữ liệu
  • Truy cập state/props, business logic

3. InteractionManager

Khi người dùng đang tương tác (chạm, vuốt) mà JS thread lại chạy tác vụ nặng thì dễ giật. InteractionManager cho phép hoãn công việc nặng sang sau khi các tương tác/animation kết thúc:

InteractionManager.runAfterInteractions(() => {
  console.log('Running after interactions');
});

Hệ thống chạm coi một hoặc nhiều lần chạm đang diễn ra là "interaction" và trì hoãn callback tới khi các chạm kết thúc/hủy. Bạn cũng có thể đăng ký animation của mình:

const handle = InteractionManager.createInteractionHandle();
// chạy animation… (các task runAfterInteractions được xếp hàng)
InteractionManager.clearInteractionHandle(handle);  // xong → task trong hàng đợi mới chạy

Kết hợp với React Navigation

Điển hình: useFocusEffect chạy ngay khi màn hình được focus — lúc animation chuyển màn hình có thể chưa xong. React Navigation chạy animation trên UI thread nên thường ổn, nhưng nếu effect cập nhật UI hoặc render nặng thì animation vẫn bị ảnh hưởng. Hoãn bằng InteractionManager:

useFocusEffect(
  React.useCallback(() => {
    const task = InteractionManager.runAfterInteractions(() => {
      // tác vụ nặng cuối cùng cập nhật UI
    });
    return () => task.cancel();
  }, [])
);
Thay thế hiện đại

Ngoài InteractionManager (API riêng của RN), có thể dùng startTransition của React để dời cập nhật không quan trọng — xem Chương 7.

Kiểm tra nhanh

1. Worklet là gì?
Worklet cho phép chạy code animation ở UI thread, không phụ thuộc JS thread.
2. Cần gọi analytics (hàm thường) từ trong useAnimatedStyle thì dùng?
runOnJS đưa lời gọi từ UI thread về JS thread.
3. InteractionManager.runAfterInteractions dùng để?
Tránh tranh chấp JS thread với animation/cử chỉ.
