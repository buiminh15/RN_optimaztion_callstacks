Concurrent React

Đôi khi không thể làm app chạy nhanh hơn về mặt vật lý — nhưng có thể làm nó cảm thấy nhanh hơn. Concurrent React cho phép tạm dừng, đổi ưu tiên hoặc bỏ qua cập nhật để các tương tác quan trọng (gõ phím, bấm) luôn được ưu tiên.

1. Ý tưởng cốt lõi

Quy tắc ngón tay cái cho hiệu năng cảm nhận: phản hồi nhanh + cập nhật trạng thái đều đặn tốt hơn bắt người dùng đợi đến khi xong hết. Đó là tinh thần của Concurrent React.

Concurrent React ra mắt trong React 18, vào React Native từ 0.69. Thay vì xử lý một mạch không ngắt, cập nhật có thể bị tạm dừng, đổi ưu tiên hoặc bỏ. Nó mở ra: interruptible rendering, time-slicing, automatic batching.

Điều kiện

Để dùng useTransition, useDeferredValue, automatic batching, Suspense for data fetching trong React Native, bạn phải chuyển sang New Architecture (mặc định từ React Native 0.76).

2. useDeferredValue — cho component nặng

Với component render tốn kém (tính toán nặng, thư viện bên thứ ba), dùng useDeferredValue để nó không chặn các tác vụ ưu tiên cao. Hình dung: bạn đang viết ghi chú, bạn bè nhìn qua vai và chen vào bình luận — bạn tạm dừng ghi chú chút. Tương tự React "tạm dừng" render phần ít quan trọng.

function DeferredScreen() {
  const [count, setCount] = useState(0);
  const deferredCount = useDeferredValue(count);
  return (
    <>
      <CounterNumber count={count} />               {/* cập nhật ngay */}
      <SlowComponent count={deferredCount} />       {/* cập nhật sau */}
      {count !== deferredCount ? <ActivityIndicator /> : null}
      <Button onPress={() => setCount(count + 1)} title="Increment" />
    </>
  );
}
Mẹo

Bọc component nặng nhận giá trị deferred bằng React.memo(), để nó không render lại vì cha re-render.

Khi fetch dữ liệu, thường ta hiện loading và nội dung biến mất rồi hiện lại — gây giật. useDeferredValue + Suspense cho phép giữ giá trị cũ đến khi dữ liệu mới sẵn sàng:

function SearchScreen() {
  const [query, setQuery] = useState('');
  const deferredQuery = useDeferredValue(query);
  const isStale = query !== deferredQuery;
  return (
    <View>
      <TextInput value={query} onChangeText={setQuery} placeholder="Search items..." />
      <Suspense fallback={<LoadingSpinner />}>
        <View style={[isStale && { opacity: 0.8 }]}>
          <SearchResults query={deferredQuery} />
        </View>
      </Suspense>
    </View>
  );
}

Lúc đầu query và deferredQuery bằng nhau. Khi gõ, query cập nhật ngay, deferredQuery giữ giá trị cũ đến khi tìm xong; kết quả mờ đi (opacity 0.8) rồi hiện kết quả mới.

3. useTransition — cho cả một cập nhật

Transition đánh dấu các cập nhật không khẩn cấp là ưu tiên thấp. Khác useDeferredValue (hoãn render một giá trị), useTransition hoãn toàn bộ quá trình cập nhật.

function TransitionScreen() {
  const [count, setCount] = useState(0);
  const [slowCount, setSlowCount] = useState(0);
  const [isPending, startTransition] = useTransition();

  const handleIncrement = () => {
    setCount(c => c + 1);                          // khẩn cấp
    startTransition(() => setSlowCount(c => c + 1)); // ưu tiên thấp
  };
  return (
    <SafeAreaView>
      <CounterNumber count={count} />
      <SlowComponent count={slowCount} />
      {isPending ? <LoadingSpinner /> : null}
      <Button onPress={handleIncrement} title="Increment" />
    </SafeAreaView>
  );
}

4. Automatic batching

React 18 gộp nhiều cập nhật state vào một lần re-render. Trước đây chỉ gộp trong event handler của React; trong Promise, setTimeout, native event… thì không.

setTimeout(() => {
  setProductQuantity(q => q + 1);
  setIsCartOpen(o => !o);
  // React 17: render 2 lần · React 18: render 1 lần (batching)
}, 1000);

Batching cũng tránh trạng thái "dở dang" (mới cập nhật một nửa state) gây glitch hình ảnh.

Kiểm tra nhanh

1. Điều kiện để dùng useTransition/useDeferredValue trong React Native?
Các tính năng concurrent cần New Architecture (mặc định từ RN 0.76).
2. Muốn hoãn render của một component nặng phụ thuộc giá trị gõ phím, nên dùng?
Một giá trị → useDeferredValue.
3. Automatic batching trong React 18 nghĩa là?
Giảm render thừa và tránh state dở dang.
