Xác định kích thước thật của thư viện bên thứ ba

Hệ sinh thái JS thích "đừng làm lại điều đã có". Kết quả là npm có hàng triệu thư viện và node_modules chiếm hàng GB — nhưng nhờ bundler chỉ một phần nhỏ chui vào app RN. Chương này là bộ công cụ hàng ngày để biết kích thước thật của dependency.

Website

bundlephobia.com

Nhập tên package npm → kích thước minified, nén (gzip), và cả thời gian tải (hữu ích hơn cho web). Có phân rã package và dependency của nó, giống react-native-bundle-visualizer (chương sau).

Website · dự phòng

pkg-size.dev

Khi Bundlephobia từ chối một package hoặc bị sập. Cài package vào một container web và hiển thị kích thước minified & nén.

IDE · thời gian thực

Import Cost (VS Code)

Hiển thị kích thước import ngay cạnh code (cả trên Cursor…). Chạy import qua Webpack — vốn không hỗ trợ RN nên thường thất bại với package có code native, nhưng dùng tốt với phần còn lại.

Thực hành · Chọn công cụ phù hợp

Bạn đang ở tình huống nào?

Giới hạn chung

Các số liệu từ web là tham khảo: chúng đo theo bundler web, không phải Metro + Hermes bytecode. Số cuối cùng phải xác nhận bằng cách phân tích bundle thật (Chương 19) trước và sau khi thêm thư viện.

Mẹo

Bạn có thể dùng Webpack hoặc Rspack làm bundler cho dự án RN qua Re.Pack — khi đó Import Cost cũng có thể phản ánh đúng hơn.
